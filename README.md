# Meta Attack Language Attack Graph Simulator

Imitates securiCAD by foreseeti

## Features

- **Accurate Simulation**: Event-driven simulation engine
- **Hidden Node Support**: Handles hidden nodes in visualization while maintaining simulation accuracy
- **Visualization**: Generates multiple types of visualizations including critical paths, all paths, and TTC distributions
- **Defense Modeling**: Support for defense nodes and probabilistic security controls
- **Multiple Entry Points**: Simultaneous analysis from multiple attack vectors

## Requirements

- Python 3.7 or higher
- NumPy 1.20.0 or higher
- Matplotlib 3.3.0 or higher
- Graphviz 0.16 or higher
- PyYAML 5.4.0 or higher

## Installation
Download the "sim" directory
```bash
cd sim
pip install -e .
```

## Usage

### Basic Command Structure
```bash
sim [yaml_file] [entry_point_count] [entry_points...] [target] [iterations] [options]
```

### Arguments

| Argument | Type | Description |
|----------|------|-------------|
| `yaml_file` | string | Path to the attack graph YAML file |
| `entry_point_count` | integer | Number of entry points (1-5) |
| `entry_points` | string(s) | Names of entry point nodes |
| `target` | string | Name of target node |
| `iterations` | integer | Number of simulation iterations |

### Options

| Option | Description |
|--------|-------------|
| `-h, --hide-hidden` | Hide nodes with 'hidden' tag in visualizations |
| `-a, --allpaths` | Generate allpaths.png in addition to critical paths |
| `--help` | Show detailed help message |
| `--version` | Show version information |

### Examples

**Basic Single Entry Point Analysis:**
```bash
sim attackgraph.yml 1 Asset1:attackStep1 Target:targetAttackStep 1000
```

**Multiple Entry Points with High Iteration Count:**
```bash
sim attackgraph.yml 3 Asset1:attackStep1 Asset2:attackStep2 Asset3:attackStep3 Target:targetAttackStep 10000
```

**Advanced Analysis with Hidden Node Filtering:**
```bash
sim complex_attackgraph.yml 2 Asset1:attackStep1 Asset2:attackStep2 Target:targetAttackStep 5000 -h
```

**Complete Visualization with All Paths:**
```bash
sim network_attackgraph.yml 1 Asset1:attackStep1 Target:targetAttackStep 2000 -a -h
```

## Output Files

The simulator generates multiple output files for comprehensive analysis:

### critical_paths.png (Always Generated)
- **Purpose**: Shows the most frequently used attack paths from simulation results
- **Content**: Nodes and edges with frequency-based styling
- **Edge Colors**: 
  - Red (thick): High frequency paths (≥70% of simulations)
  - Orange (medium): Medium frequency paths (≥40% of simulations)  
  - Yellow (thin): Low frequency paths (<40% of simulations)
- **Use Case**: Identifying the most critical vulnerabilities and attack vectors

### allpaths.png (Generated with -a option)
- **Purpose**: Complete view of all possible attack paths from entry points to target
- **Content**: All reachable nodes and connections in the attack graph
- **Use Case**: Understanding the complete attack surface and potential attack vectors
- **Recommended**: For initial analysis and comprehensive security assessment

### global_ttc.png (Always Generated)
- **Purpose**: Statistical analysis of Time-to-Compromise across all successful simulations
- **Content**: Cumulative distribution function (CDF) showing probability vs time
- **Interpretation**: 
  - X-axis: Time to compromise (arbitrary time units)
  - Y-axis: Cumulative probability (percentage of successful attacks)
- **Use Case**: Risk assessment and security planning based on attack timing

## YAML File Format

The simulator expects attack graphs in YAML format generated by "attack-graph generate" command by maltoolbox.

### Basic Node Structure
```yaml
attack_steps:
  NodeName:
    id: 1                    # Unique integer identifier
    type: "or"               # Node type: "or", "and", "defense", "exist"
    asset: "AssetName"       # Associated asset name
    ttc:                     # Time-to-Compromise distribution
      name: "Exponential"    # Distribution type
      arguments: [1.0]       # Distribution parameters
    parents:                 # Parent node relationships
      parent_id: "relationship_type"
    children:                # Child node relationships  
      child_id: "relationship_type"
    tags: ["hidden"]         # Optional tags (e.g., "hidden" for visualization)
    is_necessary: "True"     # Required for AND node logic
```

### Node Types

**Attack Steps (type: "or" or "and"):**
- **OR nodes**: Activated when any parent is completed
- **AND nodes**: Activated when all necessary parents are completed
- **is_necessary**: Controls whether parent is required for AND nodes

**Defense Nodes (type: "defense"):**
```yaml
DefenseName:
  id: 100
  type: "defense"
  defense_status: 0.7      # Probability of blocking attack (0.0-1.0)
  children:
    target_node_id: "defends"
```

**Existence Nodes (type: "exist"):**
```yaml
ExistenceName:
  id: 200
  type: "exist"
  existence_status: "True"  # Whether the condition exists
  children:
    dependent_node_id: "requires"
```

### Time-to-Compromise Distributions



| Distribution | Parameters | Example | Use Case |
|-------------|------------|---------|----------|
| `Exponential` | [rate] | `[1.0]` | Standard attack timing |
| `Gamma` | [shape, scale] | `[2.0, 1.0]` | Multi-stage attacks |
| `LogNormal` | [mean, sigma] | `[0.0, 1.0]` | Variable skill attacks |
| `Uniform` | [min, max] | `[0.5, 2.0]` | Bounded attack windows |
| `Bernoulli` | [probability] | `[0.8]` | Success/failure attacks |
| `TruncatedNormal` | [mean, variance] | `[5.0, 2.0]` | Normally distributed with lower bound |
| `Pareto` | [scale, shape] | `[1.0, 2.0]` | Heavy-tailed distributions |

**Predefined Distributions:**
- `EasyAndCertain`: Quick, reliable attacks
- `EasyAndUncertain`: Quick but unreliable attacks  
- `HardAndCertain`: Slow but reliable attacks
- `HardAndUncertain`: Slow and unreliable attacks
- `VeryHardAndCertain`: Very slow but reliable attacks
- `VeryHardAndUncertain`: Very slow and unreliable attacks

## Troubleshooting

### Common Issues and Solutions

**File Not Found Errors:**
```bash
# Verify file exists and path is correct
ls -la your_graph.yml           # Linux/macOS
dir your_graph.yml              # Windows
```

**Node Name Not Found:**
- Check exact spelling and case sensitivity in YAML file
- Verify node names match between command line and YAML file
- Use quotes for node names containing special characters

**Graphviz Installation Issues:**
```bash
# Install system graphviz package
sudo apt install graphviz        # Ubuntu/Debian
brew install graphviz           # macOS
# Windows: Download from graphviz.org
```

**Memory Issues with Large Iterations:**
- Reduce iteration count for testing
- Monitor system memory usage
- Consider running analysis in smaller batches

**Performance Issues:**
- Use smaller graph subsets for initial analysis
- Reduce visualization complexity with `-h` option
- Consider distributed analysis for very large problems

### Error Messages

**"Target not reachable from entry points":**
- Verify attack paths exist in the graph structure
- Check for disconnected components in the attack graph
- Ensure proper parent-child relationships in YAML

**"No valid paths found":**
- Check defense configurations (may be blocking all paths)
- Verify existence conditions are properly set
- Review AND node logic and necessary parent requirements
